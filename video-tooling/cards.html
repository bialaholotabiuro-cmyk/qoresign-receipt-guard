How it works

One receipt, two signatures, one anchor

1 · ReceiptCanonical JSON in the browser → SHA-256 fingerprint
→
2 · Hybrid signatureWallet signs the fingerprint text: secp256k1 + ML-DSA-87 (4,627-byte PQ half)
→
3 · Anchor txHybrid-signed 1 uqor self-send, memo qrg1:<sha256> on qorechain-diana
→
4 · VerifierServer side, @qorechain/qoresign: signature vs on-chain key, tx read-back

Proof card = receipt + hybrid signature + anchor tx hash. Anyone can re-check it against the public chain.

Post-quantum correctness

What the verifier insists on

  • ML-DSA-87 half checked against the key registered on chain, never a key sent by the page
  • Stripped PQ half (downgrade) or wrong ML-DSA-87 key → rejected (unit tests)
  • Any edit to the receipt → fingerprint, signature and memo checks fail
  • Anchor tx must be committed, signed by the issuer, tier pqc with a verified ML-DSA-87 layer
